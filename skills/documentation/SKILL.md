# Documentation & Comments Skill

Activate this skill when documenting modules, writing API specs, updating READMEs, or adding inline code comments.

## 1. Comment Philosophy: Document "Why", Not "What"
- **Good Comments:** Explain non-obvious business logic, security decisions, concurrency constraints, or workarounds for external bugs.
- **Bad Comments:** Merely restate what the code clearly does (e.g. `// increment i`).

## 2. Evidence-Based Project Docs
- Documentation must accurately reflect actual codebase state and verifiable commands.
- Do not create placeholder "TODO" documentation for core system capabilities.
- Keep documentation modular, concise, and structured with markdown tables and lists.
